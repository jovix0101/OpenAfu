# 04 · 体成分模型：12 项指标其实只有一个自由变量

> 全部数值为**合成演示值**（175 cm / 1984 年生 / 男 / 78.40 kg / 阻抗 505～515 Ω）。
> 模型系数是公开生理公式与本设备的形式拟合，不是任何人的真实体检数据。

## 1. 观察：App 给的 12 项指标不是 12 个独立测量

App 的「身材管理」页一次会给出：体重、体脂率、脂肪量、去脂体重、体水分量 / 率、蛋白质量 / 率、肌肉量 / 率、骨骼肌量 / 率、基础代谢……看起来像秤测了十几种东西。

把其中一组数值互相除一下会发现：**它们全部由「去脂体重 FFM」这一个量导出**。

设体重 `W`、去脂体重 `F`：

| 指标 | 表达式 | 系数（本设备） |
| --- | --- | --- |
| 脂肪量 | `W − F` | — |
| 体脂率 | `(W − F) / W` | — |
| 体水分量 | `0.6318 · F` | 体水分率 = / W |
| 蛋白质量 | `0.3107 · F` | 蛋白率 = / W |
| 肌肉量 | `0.9509 · F` | 肌肉率 = / W |
| 骨骼肌量 | `0.4387 · F` | 骨骼肌率 = / W |
| 基础代谢 BMR | `370 + 21.6 · F` | Katch-McArdle |
| BMI | `W / H²` | H 单位 m |
| FFMI | `F / H²` | 归一化：`FFMI + 6.1·(1.8 − H)` |
| FMI | `(W − F) / H²` | — |
| 目标体重 | `F / (1 − 目标体脂率)` | 默认 20% |

反过来说：**只要能算出 F，其余 11 项都是四则运算**。而秤给的两个原始量是 `W` 和两路阻抗 `Z1 / Z2`。

## 2. 从阻抗到 FFM

生物电阻抗的常识形式：`FFM ∝ H² / Z`（身高越高、导电路径越长；阻抗越低、含水组织越多）。于是取

```
Z_avg = (Z1 + Z2) / 2
FFM  = k · H² / Z_avg          # H 用 cm，k 是待标定常数
```

`k` 不需要知道物理单位，只要有一组「App 算出的体脂率 + 同一时刻的体重 / 阻抗」就能反推：

```
F = W · (1 − fatPct)
k = F · Z_avg / H²
```

用三个彼此独立的锚点交叉验证（合成演示值，H = 175 cm，`k·H² ≈ 29976`）：

| 锚点 | 体重 | 体脂率 | Z_avg | 反推的等效阻抗 `k·H²/F` |
| --- | --- | --- | --- | --- |
| A | 79.00 kg | 24.1% | 500 Ω | 499.9 Ω |
| B | 78.60 kg | 25.5% | 512 Ω | 511.9 Ω |
| C | 78.80 kg | 24.7% | 505 Ω | 505.2 Ω |

三者落在 ±0.3% 内，说明「FFM ∝ H²/Z」的形式对这台设备是够用的。把 `k` 固定后，之后每次测量都能**完全离线**算出全套指标，不需要联网、不需要 App。

## 3. 一次完整演算（合成值）

输入：`W = 78.40 kg`、`Z1 = 505 Ω`、`Z2 = 509 Ω`、`H = 175 cm`、`k = 0.9788`

```
Z_avg = 507.0
FFM   = 0.9788 × 175² / 507.0 = 59.12 kg
fatKg = 78.40 − 59.12 = 19.28 kg        → 体脂率 24.6%
water = 0.6318 × 59.12 = 37.34 kg       → 47.6%
protein = 0.3107 × 59.12 = 18.37 kg     → 23.4%
muscle  = 0.9509 × 59.12 = 56.22 kg     → 71.7%
skel    = 0.4387 × 59.12 = 25.94 kg     → 33.1%
BMR     = 370 + 21.6 × 59.12 = 1647 kcal
BMI     = 78.40 / 1.75² = 25.6
FFMI    = 59.12 / 1.75² = 19.3
FMI     = 19.28 / 1.75² = 6.3
TDEE    = BMR × 1.2 = 1976 kcal（久坐）
目标体重 = 59.12 / 0.80 = 73.9 kg（体脂 20%）
```

这些与 App 显示的对应项逐项吻合（差值来自四舍五入 / 分度值）。

## 4. 派生指标的正确解释

| 指标 | 是什么 | 不是什么 |
| --- | --- | --- |
| BMR（基础代谢） | 由 FFM 算的 Katch-McArdle 估计值 | 不是秤测的；不随当天活动变化 |
| TDEE（每日消耗） | `BMR × 活动系数`（1.2 久坐 / 1.375 轻活动 / 1.55 中等活动） | **是假设不是测量**；系数靠用户自己选，App 没给 |
| FFMI | 去脂体重指数，衡量肌肉量相对身高 | 分档阈值男女不同，别直接套健美标准 |
| 目标体重 | 保持当前 FFM、把体脂降到目标值时的体重 | 不是医学建议 |
| 肌肉脂肪比 | `肌肉量 / 脂肪量` | 只是个比值 |
| 上次差值 | 与上一次存档记录的体重差 | 不是秤给的（秤屏上那个小数字是秤自己算的） |

**回答一个常被问到的问题**：BMR / TDEE 会随身高、体重变化吗？——会随**去脂体重**变化（因为 `BMR = 370 + 21.6·FFM`），FFM 又由 `H²/Z` 决定；但纯脂肪增加不会提高 BMR，身高只通过 `H²` 进入模型。所以改「资料」里的身高会连带改变历史曲线的体脂率，这符合模型，不是 bug。

## 5. 边界与误差来源

- **k 是个体化的**：用一个人的锚点标定，换个人（性别、年龄、体型）会有系统偏差。要多人用，最好每人各标一次。
- **阻抗受状态影响**：脚是否干燥、是否刚运动 / 洗澡 / 吃饭、室温，都会让 Z 漂几十 Ω，体脂率能差好几个百分点。看趋势别看单次。
- **两路阻抗不是两个独立测量**：取平均是简化；`size==5` 的机型有五路 ADC，映射顺序不同（`ICWeightScale27Worker.java:487-500`）。
- **`adcs = [0,0]` 必须拒绝**：此时没有有效阻抗，不应该用模型硬算体脂率（会得到 100% 之类的荒谬值）。ScaleBar 里 `compute()` 有 `guard z1 > 0, z2 > 0`。
- **服务端算法是黑盒**：`ICAlgorithmManager.calc()` 是空壳（见 `03-app-internals.md`），本模型是对服务端输出的**拟合**，不是逆向出原公式。服务端若更新算法，系数需要重新标定。
- **不是医疗建议**：所有指标仅供个人趋势观察。
